# Использовалась ли BIP32 в Bitcoin Puzzle — проверка

## Что утверждает создатель

Единственное первоисточник-заявление (saatoshi_rising, bitcointalk, 2015):

> "A few words about the puzzle. There is no pattern. It is just consecutive keys
> from a deterministic wallet (masked with leading 000...0001 to set difficulty).
> It is simply a crude measuring instrument, of the cracking strength of the community."

То есть: **детерминированный (HD) кошелёк + последовательные ключи + стирание старших бит**.
«Детерминированный кошелёк» на практике = BIP32 (обычно поверх BIP39-фразы) —
это стандарт 2013–2015 гг., других массовых реализаций тогда не было.

## Что проверяемо из публичных данных (сделано в этом проекте)

1. **83 решённых ключа проверены end-to-end**: для каждого ключа #N
   (N = 1–70, 75…135) вычислено k×G → Hash160 → Base58Check — все 83 адреса
   совпали с адресами пазла. Формат: P2PKH, сжатые публичные ключи.
2. **Каждый ключ имеет ровно N бит** (лежит в [2^(N-1), 2^N)).
   Вывод: чистое обнуление старших бит (k mod 2^N) не могло использоваться —
   тогда у половины пазлов старший бит был бы 0 и ключ выпал бы из диапазона
   (вероятность совокупного совпадения 2^-83). Создатель приводил ключ
   в диапазон принудительно: `k = 2^(N-1) | (child mod 2^(N-1))`.
3. **Между соседними ключами нет арифметической связи** (нет «+1» и т.п.) —
   согласуется с гипотезой HD-дерева: дочерние ключи BIP32 псевдослучайны
   относительно друг друга.

## Что проверить НЕВОЗМОЖНО (и почему)

Сид-фраза, путь деривации (m/0'/N? m/N? другой?) и порядок индексов никогда
не публиковались. BIP32 построен на HMAC-SHA512 — функция однонаправленная:
по дочернему ключу нельзя восстановить родительский, ни мастер-ключ, ни тем
более BIP39-фразу (для неё ещё и PBKDF2 с 2048 итерациями). Поэтому:

- подтвердить криптографически, что использовался именно BIP32 (а не, скажем,
  самописный детерминированный генератор) — нельзя;
- опровергнуть тоже нельзя: все публичные данные согласуются с BIP32;
- если сид когда-нибудь всплывёт — все оставшиеся 78 ключей вычисляются
  мгновенно (пазл обнуляется), поэтому создатель его не раскрывает.

**Итог: BIP32 — рабочая и согласованная с фактами реконструкция; единственное
доказательство — слова создателя.**

## Библиотеки для цепочки BIP39 → BIP32 → ключ → адрес

| Язык | BIP39 | BIP32 | secp256k1 |
|------|-------|-------|-----------|
| Python | `mnemonic` (pure) | `bip32`, `bip_utils`, `hdwallet` | `coincurve` (быстро), `ecdsa` (pure) |
| Rust | `bip39` | `bip32` | `k256` (так собран датасет `boha`) |
| C++ | libbitcoin | libbitcoin | libsecp256k1 |

Примечание: `pip install bip32` тянет `coincurve`, который не собирается на
macOS/Python 3.13 без cmake. Поэтому `puzzle_generator.py` — реализация на
чистом stdlib (hashlib + hmac), проверенная против:
- официальных тест-векторов BIP32 (17/17 пройдены, включая hardened-ветку);
- библиотеки `mnemonic` (BIP39-сид совпал);
- 83 реальных решённых пазлов (адреса совпали).
